# Отправитель обратной связи сайта

Отдельный процесс на существующем сервере в Амстердаме. Принимает задания только
из специального API сайта, отправляет их только в подтверждённый личный чат через
`@CD_ORDER_BOT`. Не получает Telegram updates, не меняет webhook и офисные сервисы.
Почтовая отправка и уведомления о заказах в этот компонент пока не включены.

Для Strapi требуются `FEEDBACK_ENABLED=true` и отдельный случайный
`FEEDBACK_WORKER_TOKEN` (32–128 ASCII символов). Этот токен даёт доступ только к
очереди обратной связи. Не использовать токен администратора Strapi или CRM.
В production Strapi должен слушать loopback, а Nginx — переписывать `X-Real-IP`.
На публичном URL `/api/feedback` задать `client_max_body_size 16k`, не меняя лимит
загрузки изображений и заказов. Все остальные маршруты имеют прежние лимиты.

Скопировать исходники отправителя в отдельную папку `/srv/docker/cd-site-feedback`.
Создать отдельный `.env` по примеру, доступный только владельцу. Каталог состояния
`/srv/data/cd-site-feedback` должен быть доступен uid/gid 1000 и иметь режим 0700.
Рабочие настройки офисного бота не перезаписывать. Новые входящие порты не нужны.

Прежде чем включать процесс, проверить личный чат и бота через `getMe/getChat`,
новую таблицу и сохранение в изолированной базе, недоступность обоих API,
защиту от повторной отправки и ошибочного получателя. Учесть нагрузку общей VM.
По умолчанию отправитель отключён. Тесты не используют рабочие ключи и сеть.

Сообщение остаётся в Strapi независимо от результата доставки. Рабочая аренда
задания — 90 секунд, максимум 8 попыток с увеличением задержки; после этого запись
остаётся в состоянии failed и доступна администратору. Локальные квитанции позволяют
повторять подтверждение после принятой Telegram отправки без второго сообщения.
При обрыве до получения ответа Telegram или сбое записи квитанции дубликат всё ещё
возможен: гарантии exactly-once у Telegram sendMessage нет.

## Остановка и откат

Остановить только контейнер `cd-site-feedback-worker`; входящие обращения сохранятся.
Для остановки приёма поставить `FEEDBACK_ENABLED=false` и перезапустить только Strapi
по согласованной процедуре. Вернуть frontend при необходимости.
**Не удалять новый content type при обычном откате:** Strapi может удалить таблицу
со всеми принятыми обращениями. Сохранить schema.json и данные, отключить обработчики
и отправителя. Перед изменением схемы проверить резервную копию и восстановление.
