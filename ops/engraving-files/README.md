# Макеты гравировки

Макеты хранятся отдельно от публичной медиатеки и PostgreSQL: `ENGRAVING_UPLOADS_DIR` — абсолютный приватный каталог вне `public`, `ENGRAVING_UPLOADS_ENABLED=true`. На REG: `/home/deploy/strapi_storage/engraving`, права каталогов 700, файлов 600. Без флага загрузки отключены, обычные заказы работают.

До 3 файлов по 10 MiB на корзину, JPG/PNG/PDF/SVG. Проверка содержимого и размера, строгий SVG без скриптов/внешних ссылок; оригинал сохраняется. Это не антивирус: PDF проверяется по сигнатуре и завершению. Не исполнять клиентские файлы; открывать актуальными программами.

Ограничения: суммарно 1 GiB оригиналов, 10 000 записей, 4 одновременные загрузки, 60 в сутки на IP / 500 всего. При свободном месте меньше 12 GiB + 40 MiB загрузки останавливаются. Заказы без файла остаются доступны. Лимит Nginx для upload-маршрута — 10 MiB, request buffering off; отдельные rate/connection limits. Общую конфигурацию других API не менять.

Файл привязывается к ключу заказа до вызова CRM. Повтор использует тот же ключ. При неясном результате CRM файл сохраняется. Ссылка с отдельным непредсказуемым ключом помещается в описание заказа и штатные уведомления. Секрет находится во фрагменте URL, не в access log. Передавать ссылку только получателям заказа. Защита по ссылке не равнозначна персональной авторизации сотрудника.

## Обслуживание

`management.py maintain --root /home/deploy/strapi_storage/engraving` очищает только непривязанные файлы старше 7 дней и оборванные загрузки старше часа. Макеты принятых/неопределённых заказов не удаляет. Ежедневный снимок SQLite + оригиналы, проверка SHA каждого файла, состава архива и gzip CRC; остаются две копии. Таймер ежечасный, копия не чаще чем раз в 23 часа. Максимум около 3 GiB постоянно (оригиналы + 2 копии), до 4 GiB при создании новой копии, плюс небольшой объём метаданных. Предыдущие копии удаляются только после проверки новой.

Установить скрипт в `/usr/local/lib/cocktaildesign-engraving/management.py` и два unit из этой папки. Сервис работает через общий space-guard, не одновременно со сборкой/общим backup. Проверять `systemctl status cocktaildesign-engraving-maintenance.timer`, журнал service и `management.py stats --root ...`.

Автоматической передачи на выключенный ПК нет. В handover workspace есть `python tools/engraving_archive.py`: перенос последней копии в `D:\Cocktail Design Backups\REG-RU\engraving` с полной проверкой и квитанцией. Оригиналы остаются на сервере. Опция `--prune-older-than-90-days` после подтверждённой локальной копии переносит в архив только файлы заказов с подтверждённым CRM ID, старше 90 дней. Неопределённые заказы исключены. После этого старая ссылка сообщает об архиве, файл выдаёт менеджер из копии на ПК. Периодический запуск/уведомление о квоте требует отдельного расписания; жёсткая квота работает независимо от ПК.

## Восстановление и откат

Проверить архив командой `management.py verify --archive /absolute/copy.tar.gz`. Восстанавливать `metadata.sqlite` и `blobs/` в новый приватный каталог из одного проверенного снимка; сначала сверить SHA и испытать скачивание в изоляции. Не накатывать старую SQLite поверх действующей: потеряются новые привязки. Не восстанавливать PostgreSQL ради отката UI.

Предпочтительный быстрый откат — предыдущий frontend: backend продолжает обслуживать уже принятые макеты. Полный откат backend выполняется с временным запретом оформления и сохранением приватного каталога; сначала убедиться, что открытые старые вкладки не отправят макеты в сервер, который их игнорирует. `ENGRAVING_UPLOADS_ENABLED=false` отключает и скачивание, поэтому не использовать его как штатную очистку.
